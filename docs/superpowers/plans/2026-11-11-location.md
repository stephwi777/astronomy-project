# Phase 2: Location Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let visitors set a location (current location or place search) in a centered window, remember it in the browser, show it in the header, and share it with every component through `usePlace()`.

**Architecture:** Plain-JavaScript modules in `src/place/` handle storage, names and network calls and are unit-tested with Vitest. A React Context provider holds the place and the picker's open state, saves every change, and renders one `PlaceDialog` for the whole site. The header pill reads the context to switch styles and open the picker.

**Tech Stack:** React 19, React Router 8, Vite 8, Vitest 5 (new, dev only), native `<dialog>`, Open-Meteo geocoding API, OpenStreetMap Nominatim reverse geocoding.

**Spec:** `docs/superpowers/specs/2026-11-11-location-design.md`

## Global Constraints

- Code style (user preference): sections separated by uppercase headers (`// SECTION` in JS, `/* SECTION */` in CSS, `{/* SECTION */}` in JSX) with several blank lines between sections; no other comments; only the classes that are truly needed.
- No new runtime dependencies. Vitest is the only new dev dependency.
- Only rounded coordinates (two decimal places) are stored or sent anywhere.
- `localStorage` key `starling.place`, stored value `{ version: 1, place }`.
- Sample place: `{ name: 'Kansas City', region: 'Missouri', country: 'US', latitude: 39.1, longitude: -94.58, timeZone: 'America/Chicago', source: 'sample' }`.
- Visible copy is fixed by the spec; use it verbatim (quoted in each task).
- Nothing touches the network or asks for permission until the visitor clicks.
- Commit only after the user has agreed to commits for this work.

## Review Focus

- Place names with accents or non-Latin letters ("São Paulo", "Zürich") must display unchanged in both name forms. Test in Task 2.
- Search text with spaces, `&` or accents must be URL-encoded, never break the request. Test in Task 3.
- Search results missing `admin1` or `timezone` must still become usable places (region `''`, time zone `'UTC'`); results missing coordinates are skipped. Test in Task 3.
- A query that is only spaces, or under 2 characters after trimming, must not call the API. Test in Task 3.
- Closing the window while "Finding you…" or a search is still running must not save a place or show stale results afterwards. Browser check in Task 5.

### Task 3: Place search and device location

**Files:**
- Create: `src/place/placeApi.js`
- Test: `src/place/placeApi.test.js`

**Interfaces:**
- Consumes: `roundCoordinate` from Task 1
- Produces:
  - `class SearchError extends Error`
  - `class LocationError extends Error` with `reason: 'blocked' | 'unavailable'`
  - `searchPlaces(query: string, signal?: AbortSignal) => Promise<Place[]>`: places with `source: 'search'`. Throws `SearchError` when the request fails or the response is not OK; lets an `AbortError` pass through unchanged.
  - `canUseDeviceLocation(geolocation = globalThis.navigator?.geolocation) => boolean`
  - `findDevicePlace(geolocation = globalThis.navigator?.geolocation) => Promise<Place>`: a place with `source: 'device'`. Throws `LocationError`.

- [ ] **Step 1: Write the failing tests**

Stub `fetch` with `vi.stubGlobal('fetch', vi.fn(...))` returning `{ ok, json: async () => body }`, and restore with `vi.unstubAllGlobals()` after each test. Fake geolocation is an object whose `getCurrentPosition(success, error, options)` calls `success({ coords: { latitude, longitude } })` or `error({ code })`.

```js
test('search turns Open-Meteo results into places', async () => {
  stubFetch({ results: [{ name: 'Kansas City', admin1: 'Missouri', country: 'United States', country_code: 'US', latitude: 39.09973, longitude: -94.57857, timezone: 'America/Chicago' }] })
  expect(await searchPlaces('Kansas City')).toEqual([
    { name: 'Kansas City', region: 'Missouri', country: 'US', latitude: 39.1, longitude: -94.58, timeZone: 'America/Chicago', source: 'search' },
  ])
  const url = new URL(fetch.mock.calls[0][0])
  expect(url.origin + url.pathname).toBe('https://geocoding-api.open-meteo.com/v1/search')
  expect(Object.fromEntries(url.searchParams)).toEqual({ name: 'Kansas City', count: '6', language: 'en', format: 'json' })
})

test('search text is URL-encoded', async () => {
  stubFetch({})
  await searchPlaces('Saint-Étienne & co')
  expect(new URL(fetch.mock.calls[0][0]).searchParams.get('name')).toBe('Saint-Étienne & co')
})

test('no results gives an empty list', async () => {
  stubFetch({})
  expect(await searchPlaces('Kansass')).toEqual([])
})

test('missing region and time zone are filled in, missing coordinates are skipped', async () => {
  stubFetch({ results: [
    { name: 'Monaco', country_code: 'MC', latitude: 43.73, longitude: 7.42 },
    { name: 'Nowhere', country_code: 'XX' },
  ] })
  expect(await searchPlaces('Monaco')).toEqual([
    { name: 'Monaco', region: '', country: 'MC', latitude: 43.73, longitude: 7.42, timeZone: 'UTC', source: 'search' },
  ])
})

test('short or blank queries never call the API', async () => {
  stubFetch({})
  expect(await searchPlaces('   ')).toEqual([])
  expect(await searchPlaces(' K ')).toEqual([])
  expect(fetch).not.toHaveBeenCalled()
})

test('a failed search throws SearchError', async () => {
  stubFetch({}, false)
  await expect(searchPlaces('Kansas City')).rejects.toBeInstanceOf(SearchError)
  vi.stubGlobal('fetch', vi.fn(async () => { throw new TypeError('offline') }))
  await expect(searchPlaces('Kansas City')).rejects.toBeInstanceOf(SearchError)
})

test('an aborted search passes the AbortError through', async () => {
  vi.stubGlobal('fetch', vi.fn(async () => { throw new DOMException('aborted', 'AbortError') }))
  await expect(searchPlaces('Kansas City')).rejects.toMatchObject({ name: 'AbortError' })
})

test('device location rounds coordinates and names the town', async () => {
  stubFetch({ address: { city: 'Kansas City', state: 'Missouri', country_code: 'us' } })
  const place = await findDevicePlace(fakeGeolocation({ latitude: 39.09973, longitude: -94.57857 }))
  expect(place).toEqual({ name: 'Kansas City', region: 'Missouri', country: 'US', latitude: 39.1, longitude: -94.58, timeZone: Intl.DateTimeFormat().resolvedOptions().timeZone, source: 'device' })
  const url = new URL(fetch.mock.calls[0][0])
  expect(url.origin + url.pathname).toBe('https://nominatim.openstreetmap.org/reverse')
  expect(Object.fromEntries(url.searchParams)).toEqual({ format: 'jsonv2', lat: '39.1', lon: '-94.58', zoom: '10', 'accept-language': 'en' })
})

test('the name comes from city, town, village, hamlet or county, in that order', async () => {
  stubFetch({ address: { village: 'Parkville', county: 'Platte County', state: 'Missouri', country_code: 'us' } })
  expect((await findDevicePlace(fakeGeolocation({ latitude: 39.19, longitude: -94.68 }))).name).toBe('Parkville')
})

test('a failed or nameless lookup still returns "Your location"', async () => {
  stubFetch({}, false)
  expect(await findDevicePlace(fakeGeolocation({ latitude: 1, longitude: 2 }))).toMatchObject({ name: 'Your location', region: '', country: '', source: 'device' })
  stubFetch({ address: { road: 'Main Street' } })
  expect((await findDevicePlace(fakeGeolocation({ latitude: 1, longitude: 2 }))).name).toBe('Your location')
})

test('geolocation errors become blocked or unavailable', async () => {
  await expect(findDevicePlace(failingGeolocation(1))).rejects.toMatchObject({ reason: 'blocked' })
  await expect(findDevicePlace(failingGeolocation(2))).rejects.toMatchObject({ reason: 'unavailable' })
  await expect(findDevicePlace(failingGeolocation(3))).rejects.toMatchObject({ reason: 'unavailable' })
})

test('geolocation asks for city-level accuracy with a 10 second limit', async () => {
  stubFetch({})
  const geolocation = fakeGeolocation({ latitude: 1, longitude: 2 })
  await findDevicePlace(geolocation)
  expect(geolocation.lastOptions).toEqual({ enableHighAccuracy: false, timeout: 10000, maximumAge: 600000 })
})

test('canUseDeviceLocation is false without geolocation', () => {
  expect(canUseDeviceLocation(undefined)).toBe(false)
  expect(canUseDeviceLocation(fakeGeolocation({ latitude: 1, longitude: 2 }))).toBe(true)
})
```

### Task 5: The location window

**Files:**
- Create: `src/components/PlaceDialog.jsx`, `src/components/PlaceDialog.css`
- Modify: `src/place/PlaceContext.jsx` (render `<PlaceDialog />` once, after `children`)

**Interfaces:**
- Consumes: `usePlace()` (Task 4); `searchPlaces`, `canUseDeviceLocation`, `findDevicePlace`, `SearchError`, `LocationError` (Task 3)
- Produces: `PlaceDialog()`, no props

- [ ] **Step 1: Implement the window shell**

A `<dialog>` with a ref.
- When `pickerOpen` turns true, call `showModal()`. When it turns false, call `close()`.
- The dialog's `close` event calls `closePicker()`.
- All visible content sits in an inner wrapper that carries the padding, and the `<dialog>` itself has `padding: 0`. That way a click whose `event.target` is the `<dialog>` element itself can only be on the backdrop, and it closes the window.
- Copy:
  - title `<h2>`: "Where are you stargazing?"
  - line under it: "We'll tailor the sky to your spot."
  - × button: `aria-label="Close"`
- Label the dialog with `aria-labelledby` pointing to the title.
- When the window closes, reset the query, results, status and device message, and stop pending work: abort the search controller and ignore any device result that arrives later.

- [ ] **Step 2: Implement "Use my current location"**

Render the button only when `canUseDeviceLocation()` is true, and give it `autoFocus`. When the button is missing, give the search input `autoFocus` instead.
- While waiting, the button is disabled and reads "Finding you…".
- On success, call `setPlace(place)` then `closePicker()`.
- On `LocationError`, show the message under the button, then:
  - `'blocked'`: "Location access is blocked. You can search for a place instead.", and focus the search input.
  - `'unavailable'`: "We couldn't find you just now. Try again, or search for a place."

- [ ] **Step 3: Implement the place search**

A `<form role="search">` containing a visible `<label>` "Search for a place" and an `<input type="search">`.
- Typing schedules a search 300 ms after the last keystroke. Submitting the form searches immediately.
- Every search creates a new `AbortController` and aborts the previous one, and `AbortError`s are ignored.
- Results are a `<ul>` of `<button type="button">`s: the name in `<strong>`, then a `<span>` with the region and country code joined by ", ", skipping empty parts (for example "Missouri, US"). Choosing one calls `setPlace` then `closePicker()`.
- One status `<p>` with `aria-live="polite"`. Copy:
  - "6 places found" / "1 place found"
  - "No places match 'QUERY'. Check the spelling or try a nearby town." (QUERY is the trimmed text)
  - "Search isn't working right now. Check your connection and try again."
  - Empty while the query is under 2 characters.

- [ ] **Step 4: Style `PlaceDialog.css`**

Match the approved mockup:
- **Panel:** `var(--high)` background, `2px solid var(--far-hills)` border, 18px radius, width `min(420px, 100vw - 32px)`.
- **Backdrop:** `::backdrop` in `rgb(11 13 43 / 0.75)`.
- **Title:** Fraunces, `var(--moon)`.
- **Current-location button:** a full-width pill in `var(--far-hills)`.
- **Search input:** `var(--frost)` with `var(--ink)` text and at least 1rem font.
- **Results:** scroll inside the panel with `max-height: 40vh`; a result button gets `var(--far-hills)` on hover and focus.
- **Errors:** the device message uses `var(--mist)`, not red.

- [ ] **Step 5: Check in the browser**

On `/starling/`:
1. The pill opens the window, with focus on "Use my current location".
2. Escape, ×, and a backdrop click each close it without changing the pill, and focus returns to the pill.

6. Use the browser's location emulation (or a stubbed `navigator.geolocation`) for success, blocked and timeout. Each shows the right result or message, and blocked moves focus to the search box. Closing the window during "Finding you…" saves nothing.
7. At 375px wide, the window fits with no sideways scroll.
8. The console has no errors, and `npm run lint`, `npm test` and `npm run build` pass.
